# 八模型轮转互审（第 01 轮）

## 结论

本轮对旧版 440 条候选执行了八模型轮转抽样语义审核。每个生成模型在每个生成项的 5 条候选中固定抽取 2 条，由轮转中的另一个模型审核，共完成 176 次 API 审核。接口失败 0 次，自审 0 次；其中 2 个任务首次尝试失败后重试成功。

审核结果为 175 条拒绝、1 条需要修改、0 条接受。这一结果不能直接用于比较八个生成模型的相对能力：440 条候选产生于通用判分契约加入之前，全部缺少 `scoring_contract`，因此 176 条抽样候选的“客观可判分性”全部不通过。该结果证明旧候选不适合并入当前正式数据集，也说明后续模型赛马必须使用新版生成 Prompt 和通用判分契约。

## 审核设置

固定轮转关系如下，左侧模型审核右侧模型生成的数据：

| 审核模型 | 被审核数据的生成模型 |
| --- | --- |
| GPT 5.6 Luna | DeepSeek V4 Flash |
| DeepSeek V4 Flash | Gemini 3.7 Flash |
| Gemini 3.7 Flash | GPT 5.6 Sol |
| GPT 5.6 Sol | Claude Opus 5 |
| Claude Opus 5 | 智谱 5.3 Flash |
| 智谱 5.3 Flash | DeepSeek V4 Pro |
| DeepSeek V4 Pro | 通义千问 3.8 Flash |
| 通义千问 3.8 Flash | GPT 5.6 Luna |

抽样使用生成项名称、生成模型和候选唯一编号的 SHA-256 排序，同一批数据重复运行会选中相同候选。每个生成项产生 16 个审核任务，11 个生成项共 176 个；每个生成模型被审核 22 条，每个审核模型承担 22 条。

每次审核保存接受、需要修改或拒绝的结论，以及九个维度的分数、通过状态、具体理由、字段证据、关键问题、修改建议和置信度。原始请求、原始响应、全部尝试、Token 用量、耗时和接口元数据均单独保留，审核程序不修改候选数据。

## 证据与边界

机器清单位于 `data/candidate_reviews/八模型轮转互审-第01轮/rotation_manifest.json`，逐任务状态位于同目录的 `job_results.jsonl`，汇总位于 `semantic_summary.json`，单条请求、响应和审核意见位于 `model_reviews/`。该目录包含原始 API 证据，由 Git 忽略；本文档保存可提交的结论。

旧版 `data/candidate_reviews/试审-第01轮/` 共 182 个文件在本轮前后逐文件 SHA-256 一致，原有 44 次审核没有被覆盖或修改。

本轮只审核每个模型、每个生成项的 5 条候选中的 2 条，未抽中的 264 条仍只有本地确定性审核结果。由于旧候选统一缺少新版判分契约，本轮结果用于确认旧批次的结构性缺陷，不用于选择主力生成模型。生成模型赛马应改用新版 Prompt，在相同通用判分契约下重新生成和轮转审核。

## 复现命令

```powershell
.\.venv\Scripts\python.exe scripts\review_candidate_rotation.py --dry-run
.\.venv\Scripts\python.exe scripts\review_candidate_rotation.py --workers 8
```

第二条命令可续跑；已有且能通过本地结果校验的单条审核会被复用，不重复调用 API。
