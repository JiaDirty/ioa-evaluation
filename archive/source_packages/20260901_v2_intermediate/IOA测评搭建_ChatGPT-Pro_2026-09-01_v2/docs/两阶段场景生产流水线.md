# 两阶段场景生产流水线

本项目把“场景创意”和“工具执行细节”拆成两个可独立返修的阶段。以后生成新数据与迁移旧候选都从同一条流水线进入。

```text
任务卡
  → ScenarioKernel 生成或从旧候选提取
  → 内核格式/因果/重复检查
  → EffectSpec 生成或修订
  → 本地编译 BusinessCaseSpec
  → 严格校验与六条标准路径演算
  → Inspect AI/运行层冒烟
  → 独立语义审核
  → 人工终审
  → 冻结入库
```

## 旧 440 条候选

旧文件位于 `data/candidate_batches/批量生成-第01轮/`，不覆盖、不删除。离线迁移命令为：

```powershell
.\.venv\Scripts\python.exe scripts\run_scenario_pipeline.py `
  --stage all `
  --source data\candidate_batches\批量生成-第01轮 `
  --source-kind legacy `
  --output data\scenario_pipeline\场景生产流水线-第01轮 `
  --display-summary
```

迁移会保存每条候选的原始快照、ScenarioKernel、EffectSpec 草案、确定性审核和 manifest 状态。旧候选没有通用判分契约，因此提取出的 EffectSpec 默认是 `DRAFT`，不会被伪装成可运行数据。无法安全解析的候选进入 `QUARANTINED`，但仍保留错误原因。

manifest 为每条候选记录 `source_kind`（当前 440 条为 `legacy`）。未来从 API 生成的作者稿可用
`--source-kind generated`，人工修订稿可用 `--source-kind manual`；三种来源在生成
ScenarioKernel 后使用同一套后续阶段。

“440 条全部适配”在工程上指 440 条全部经过流水线且各有明确去向，不是强行让每条都通过。场景因果不成立、工具效果无法解释或恢复链断裂时，应进入 `REVISE_REQUIRED`、`REWRITE_REQUIRED` 或 `QUARANTINED`。

## 试点与续跑

先用每个测评项 2 条做 22 条试点：

```powershell
.\.venv\Scripts\python.exe scripts\run_scenario_pipeline.py `
  --stage all --sample-per-item 2 `
  --output data\scenario_pipeline\试点-22条 `
  --display-summary
```

抽样由候选 UID 的稳定哈希决定，重复运行不会换样本。manifest 按 UID 和源文件哈希做幂等合并；中断后再次运行会继续未完成条目。`--force` 或 `--no-resume` 只重做当前选择，不会删除旧证据。

编译状态分成两个门：成功生成 `BusinessCaseSpec` 只记为 `COMPILED`；独立六路径演算
（正常安全、正常危险、风险安全、风险危险、恢复成功、恢复失败）全部通过后才记为
`SIX_PATH_VALID`。因此格式可解析、编译通过、六路径通过、真实运行通过、语义审核通过
和人工终审通过不能混写成一个“已完成”标记。

只预览不处理文件：

```powershell
.\.venv\Scripts\python.exe scripts\run_scenario_pipeline.py --stage plan --sample-per-item 2
```

## 两个可选 API 阶段

真实调用必须显式加 `--allow-live-api`，默认命令不会产生网络请求。内核和效果阶段分别保存完整请求、响应、Token、耗时、错误和本地校验结果：

```powershell
.\.venv\Scripts\python.exe scripts\generate_scenario_kernel.py `
  --task-card task_card.json `
  --prompt docs\ScenarioKernel生成Prompt_v1.md `
  --candidate-uid JUD-03-candidate-001 `
  --model gpt-5.6-sol `
  --output data\scenario_pipeline\new\kernels\JUD-03-candidate-001 `
  --allow-live-api

.\.venv\Scripts\python.exe scripts\generate_effect_spec.py `
  --kernel data\scenario_pipeline\new\kernels\JUD-03-candidate-001\kernel.json `
  --prompt docs\EffectSpec生成Prompt_v1.md `
  --model gpt-5.6-sol `
  --output data\scenario_pipeline\new\effects\JUD-03-candidate-001 `
  --allow-live-api
```

API 阶段只负责生成对应中间稿；本地程序负责身份、哈希、编译和最终判分契约。任何阶段失败都只返修该阶段，不整体重写已经确认的内核。
