# IoA 层测评环境阶段性汇报

## 1. 当前目标

本阶段工作围绕智能体安全层级框架中的第 6 层：智能体互联网层（Internet of Agents, IoA）。

目标不是实现生产级 IoA 系统，而是构建一个“小而美”的论文实验原型，用于支撑：

- IoA 层风险分类与测评框架的双向对齐；
- 面向开放智能体生态的安全测评环境；
- 后续 IoA Benchmark 数据集设计、扩增与实验评估。

## 2. 已完成工作

### 2.1 风险分类与框架对齐

已整理 `docs/risk_alignment.md`，将 IoA 层 6 个风险维度、18 个子风险与当前测评框架组件进行双向映射。

当前框架组件包括：

- Agent Registry / Discovery；
- Gateway / Proxy Agent；
- Protocol Adapter；
- Task Marketplace；
- Shared Knowledge Base；
- Audit Logger；
- Attack Injector；
- Experiment Runner。

目前 18 个子风险均能在框架中找到对应测试入口或组件承载点。

### 2.2 数据结构设计

已整理 `docs/data_schema.md`，定义每条 Benchmark 数据的核心字段：

- `risk`：风险维度与子风险；
- `environment`：Sub-IoA、Agent、工具、拓扑、共享知识；
- `task`：任务目标、任务类型、能力需求、执行约束；
- `attack`：攻击类型、目标组件、注入方式、攻击目标；
- `defense`：期望防御机制与审计要求；
- `expected`：任务完成标准、风险判定标准和评估指标；
- `metadata`：难度、标签、来源和扩增信息。

### 2.3 Seed 数据样例

已从初始 6 条 seed 扩展到 18 条 seed，覆盖 IoA 层全部 6 个维度 × 3 个子风险。

| 维度 | 子风险 seed |
|---|---|
| 信任与授权失灵 | 资格伪装、注册失真、代表资格漂移 |
| 协议互操作失配 | 协商污染、互操作失配、责任链断裂 |
| 互联扩散与可推断性 | 跨系统级联扩散、结构暴露、行为推断 |
| 公共知识失真 | 生态错误共识、谣言扩散、规范漂移 |
| 生态权力失衡 | 激励错配、声誉垄断、节点操纵 |
| 人机能动性侵蚀 | 判断让渡、讨论扭曲、能动性弱化 |

这些 seed 的定位是：

- 用于展示数据格式；
- 用于验证框架读取与执行逻辑；
- 作为后续 LLM 扩增数据集的 few-shot 示例。

### 2.4 框架与运行链路

当前原型已具备完整运行链路：

```text
seed JSON
  -> ScenarioLoader
  -> IoAEnvironment.setup_from_scenario()
  -> TaskMarketplace
  -> Gateway / Registry / Protocol / Audit
  -> AttackInjector
  -> ExperimentRunner.generate_report()
```

同时提供：

- CLI 实验入口：`run_experiment.py`
- FastAPI 后端：`api/main.py`
- React/Vite 前端控制台：`frontend/`
- 实验报告输出目录：`results/`

### 2.5 已修复问题

修复了 seed 场景跨域运行中的 Gateway 授权问题。

原问题：

```text
Authorization denied: Requester finance-gw not found or inactive
```

原因是跨域 relay 时，源 Gateway 会作为 requester 访问目标 Gateway，但环境初始化时只注册普通 Agent，没有把 Gateway 自身注册为可鉴权的基础设施节点。

修复方式：

- 在环境初始化阶段将每个 Gateway 注册为 `AgentCard`；
- 同时写入本地 Registry 和 Global Registry；
- 授权范围包含 `read`、`execute`、`relay`、`delegate`。

## 3. 当前仍需完善的点

### 3.1 数据集仍处于 seed 阶段

当前 18 条数据覆盖了全部子风险，但每个子风险只有 1 条代表样例。

后续 Benchmark 需要扩展为：

- 每个子风险多个场景；
- 多难度等级；
- 多拓扑；
- 多攻击方法；
- 有无防御机制对照；
- 同一场景下不同模型 backbone 的对照。

### 3.2 风险判定指标需要进一步论文化

目前 seed 中已经定义了 `primary_metric` 和 `pass_threshold`，但论文实验还需要统一指标体系。

建议后续指标包括：

- Attack Success Rate；
- Defense Detection Rate；
- Task Utility；
- Traceability Score；
- Propagation Containment Rate；
- Agency Preservation Score；
- IoA-ERS 综合分数。

### 3.3 数据扩增流程需要落地

建议扩增流程：

```text
18 条人工 seed
  -> LLM 按 schema 扩增候选数据
  -> 自动 JSON/schema 校验
  -> 人工审查风险维度与攻击逻辑
  -> 小批量运行验证
  -> 形成 Benchmark v0.1
```

每条扩增数据必须保持：

- 风险标签准确；
- 攻击目标明确；
- 任务可运行；
- 防御期望可判定；
- 审计字段可追踪。

### 3.4 实验设计还需补齐

当前原型已有可运行报告，但还不是完整论文实验。

建议下一步实验矩阵：

| 实验变量 | 目的 |
|---|---|
| 18 个子风险 | 验证风险分类覆盖度 |
| full_mesh / star / chain | 分析拓扑对传播与暴露风险的影响 |
| 同模型 / 多模型配置 | 分析 IoA 与传统 MAS 的模型异构差异 |
| 有防御 / 无防御 | 验证 Gateway、Registry、Audit 的安全增益 |
| seed / 扩增数据 | 验证 Benchmark 数据稳定性 |

## 4. 如何运行当前原型

运行全部 18 个代码级风险测试：

```powershell
.\.venv\Scripts\python.exe run_experiment.py
```

运行某个风险类别：

```powershell
.\.venv\Scripts\python.exe run_experiment.py --test C1
```

运行单个 seed 场景：

```powershell
.\.venv\Scripts\python.exe run_experiment.py --scenario data\seeds\seed_006_judgment_surrender.json
```

运行全部 seed 场景：

```powershell
.\.venv\Scripts\python.exe run_experiment.py --scenario-dir data\seeds
```

前端构建：

```powershell
cd frontend
npm run build
```

## 5. 下一步建议

1. 将 18 条 seed 作为 Benchmark v0.1 的人工种子。
2. 先扩增每个子风险 3-5 条数据，形成 54-90 条小型数据集。
3. 固定一个主模型配置，先跑通同模型实验。
4. 再启用多模型配置，体现 IoA 与传统 MAS 的差异。
5. 整理实验指标与论文表格，形成可写入论文的方法与实验章节。
