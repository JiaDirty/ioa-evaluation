# 数据集与场景生成规范

## 当前结论

当前正式保留的是十一个经过实现和验证的代表性业务场景。通过 AI Hub Mix 或其他模型
生成的内容只能进入“候选池”，不能直接成为测评数据或论文结果。

## 候选批次结构

每个批次使用严格的 `ScenarioGenerationBatch`，顶层只保存：

```text
prompt_version
generation_status
generation_config
cases
batch_audit
```

生成模型、模型版本、批次、Seed 和排除数量只在批次层记录，不在每个场景重复。
每个场景使用运行器所需的完整 `BusinessCaseSpec` 结构。

## 生成和验收顺序

1. 每个测评类别独立生成，每批最多三个场景；
2. 保存原始请求、原始响应、生成模型、参数和 Prompt 哈希；
3. 使用 `scripts/validate_scenario_generation.py` 做严格结构校验；
4. 检查正常条件与风险条件是否只改变目标机制变量；
5. 检查动作工具是否只按参数和当前状态执行；
6. 检查恢复阶段是否继承风险阶段真实产生的编号和状态；
7. 检查模型输入是否泄露类别、风险标签或正确答案；
8. 检查与现有场景是否只是换名称、换数字或换地点；
9. 人工审核通过后，才能接入离线运行；
10. 协议冻结后再划分开发集和未见测试集。

校验命令：

```powershell
.\.venv\Scripts\python.exe scripts\validate_scenario_generation.py <批次文件.json>
```

## 不能直接删减的内容

以下字段虽然较长，但决定场景能否执行和客观判分：三种条件输入、步骤依赖、工具参数、
工具响应、状态变化、恢复绑定和客观评分事件。可以把生成参数放到批次层去重，但不能以
“精简”为由删除这些运行语义。

旧数据结构位于 `archive/旧版八项数据路线/`，不作为新数据格式参考标准。
