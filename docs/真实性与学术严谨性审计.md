# IoA 测评体系真实性与学术严谨性审计

本文档记录 IoA 层测评体系中曾经可能造成学术误表述或结果假阳性的实现点，以及当前修复状态。目标是把系统表述为“可运行、可控、可复现实验 testbed”，而不是夸大为完整生产级 IoA 互联网。

## 结论摘要

当前系统已经具备 IoA 层测评闭环：场景加载、Agent/Gateway 注册、任务调度、跨域 Gateway 链路、协议适配、攻击注入、LLM Judge、审计日志、指标报告和前端展示。本轮将原先最危险的“后端失败算防御成功”“机制存在即通过”“协议假 sent”路径改为真实执行、fail-closed 或显式 invalid。

正式实验口径：

1. `execution_mode = live_llm`。Agent、攻击生成和 Judge 使用 OpenAI-compatible API。
2. AgentCard 默认绑定独立 AG2/LLM runtime。
3. Gateway 不再内存直连 agent runner，而是通过协议适配器 POST 到 Agent HTTP endpoint；本地实验 endpoint 也是真实 HTTP 边界，只是 endpoint 后端运行在同一台机器。
4. A2A/MCP/Private API 缺少 endpoint 时 fail-closed，不返回伪造成功。
5. LLM/Judge/Agent 后端失败会生成 `EvaluationStatus.INVALID`，并从 `valid_pass_rate` 排除。
6. Shared Knowledge 冲突检测使用 LLM 语义关系判断；语义 judge 不可用时相关重叠 claim 标记为 disputed/unknown，不能作为清洁知识证据。
7. 结构暴露和行为推断使用外部攻击者观测模型，不直接把完整内部 audit log 暴露给攻击者。
8. 人机能动性、激励错配、节点操纵不再因 audit/gateway/source 存在而通过，通过依据来自行为攻击是否被阻断。
9. TaskMarketplace 受 topology 约束，跨域任务会按目标 Sub-IoA 使用目标域能力需求；不可达目标或目标域执行失败不会被当作安全成功。
10. 报告中的 `utility` 现在汇总 Marketplace 在风险测试内部产生的真实任务结果，避免正式风险测试报告出现 0.00 的误导性效用值。
11. 每个 `TestResult` 现在携带 `realism` profile，并在报告 `summary.realism` 中汇总，区分机制真实、半模拟受控和概念探针三类证据强度。
12. 正式 18 项测评启用高集成度门槛：必须有 Agent in loop，必须经过 Gateway/Marketplace/任务链路，且必须给出至少两条测量证据；低集成度项会进入 `low_integration_tests`。
13. A2A 路径已从自定义 `execute_task` envelope 改为官方 A2A v1 核心 JSON-RPC 子集：`SendMessage`、`GetTask`、`CancelTask` 方法名，`A2A-Version: 1.0` 请求头，官方 Message/Task/Artifact 对象结构，以及 per-agent Agent Card 发现端点。
14. 当目标 Agent 同时支持 A2A/MCP/Private API 时，Gateway 在同安全等级协议中优先选择官方 A2A；MCP-only 和 Private-API-only Agent 仅保留在互操作失配测例中，用来真实测异构协议语义风险。
15. Gateway 已接入结构化 Decision Agent 层：TaskUnderstanding、PermissionAnalysis、HumanAgency、CapabilityMatching、ProtocolSemantics、ContentSecurity、ProvenanceVerifier、ConsensusRisk 均输出 Pydantic 决策并写入审计与 artifact metadata。
16. Registry 外部攻击面接入 RegistryRiskAgent，外部注册/更新请求在硬策略结果之外还会生成结构化注册风险判断。
17. 正式风险测试的 `require_task_completed()` 现在强制检查 artifact 中的 required Decision Agent 证据；缺少语义 Agent 证据会被标记为 `EvaluationInvalidError`，不能算作有效测评证据。
18. 本轮新增专项 Decision Agent：`DelegationDriftAgent`、`InteropSemanticMapperAgent`、`RumorAssessmentAgent`、`NormDriftAgent`、`ReputationFairnessAgent`、`IncentiveAlignmentAgent`、`RoutingManipulationAgent`、`DiscussionIntegrityAgent`、`AuditAttributionAgent`、`AgencyErosionAgent`、`SensitivityClassifierAgent`，并把 18 个风险测试的专项语义证据写入 `TestResult.details["decision_agents"]`。
19. `risk_tests` 已增加源码级绕行扫描：正式测试不得调用 `run_agent_task()`、不得使用 `env._agents` 私有 runtime map、不得直接调用 registry injection helper；Sybil、registry distortion、node manipulation 均改为外部 attack surface 或 Gateway policy 边界。
20. 数据契约新增 `TaskEnvelope`、`TaskConstraints`、`PolicyTicket`、`AuditEvent`、`GatewayPipelineStage`、`CapabilityClaim`、`ProtocolSupport`、`EndpointDescriptor` 等 Pydantic 模型；现有 `Task`、`AgentCard`、`Artifact`、`AuditEntry` 保持向后兼容并补齐设计文档字段。
21. Gateway 审计新增固定 pipeline stage 证据：`policy_enforcement`、`candidate_ranking`、`pre_delivery_security`、`http_delivery`、`post_delivery_security`、`artifact_aggregation`、`audit_finalization`；HTTP adapter 请求携带 `Authorization: Bearer testbed-token` 和 `X-Trace-Id`。
22. `run_experiment.py` 新增 `--offline-deterministic` / `--offline` / `--deterministic` 正式入口，用于复现框架级 18 项全量测评；该模式禁用 live LLM/AG2/Judge 外部调用，但仍保留 Marketplace、Gateway、ProtocolAdapter、HTTP endpoint、Decision Agent、Audit 和 Report 全链路。

## 真实性分级口径

18 个风险测试不应被表述为同等真实性。当前报告将每项测试标注为：

| 等级 | 含义 | 论文口径 |
|---|---|---|
| `mechanism_real` | 经过 Registry、Gateway、Protocol/Endpoint、Audit 等关键机制链路 | 可作为 testbed 机制验证证据 |
| `hybrid_controlled` | 有部分真实链路，但攻击、观测或语义失配由受控 harness 构造 | 可作为可复现实验探针 |
| `concept_probe` | 主要把抽象风险操作化为小规模行为/语义测量 | 不能进入正式 18 项测评，只能作为预研或附录探针 |

报告中同时统计：

- `agent_in_loop_tests`：多少测试实际让 Agent/LLM 响应进入测量；
- `gateway_mediated_tests`：多少测试经过 Gateway 或 Gateway 相关基础设施；
- `high_integration_tests`：多少测试满足高集成度门槛；
- `low_integration_tests`：不满足高集成度门槛的测试 ID；
- `meets_high_integration_floor`：正式 18 项是否全部达到高集成度要求；
- `limitations`：该批测试共同限制，例如单机 testbed、小样本、受控攻击注入等。

截至当前实现，18 项正式测评中 `mechanism_real = 5`，`hybrid_controlled = 13`，`concept_probe = 0`；18 项全部满足 Agent in loop、Gateway mediated 和 task/marketplace 链路要求。

## 严重程度分级

- P0：会导致实验结果虚高或学术结论错误，必须修。
- P1：影响真实场景贴合度，应在论文实验前修复或明确为限制。
- P2：可作为 benchmark controlled mutation，但必须在论文中说明。
- P3：工程展示或可视化增强，不直接影响核心结论。

## 当前仍需在论文中说明的边界

1. 本地 endpoint 是真实 HTTP 协议边界，但不是跨机器部署；生产论文实验可补充 Docker/多进程 endpoint。
2. A2A 已实现官方 v1 核心 JSON-RPC 子集；streaming、push notification、gRPC 和完整 SDK 互操作仍未实现，不能表述为完整 A2A 全协议栈。MCP/Private API 仍是 OpenAI-compatible testbed message shape，不等同完整官方 MCP server/client 生态。
3. 协议语义失配是 controlled mutation，用于构造可复现实验变量。
4. HMAC certificate 是 testbed 级身份认证，生产级可替换为 DID、mTLS 或证书链。
5. LLM Judge 需要专家抽样复核和多模型一致性校准。
6. 权力失衡、结构暴露和行为推断类指标仍需扩大样本量、重复运行并报告置信区间。

## 论文表述建议

可以严谨表述为：

> We implement a controllable IoA-layer security evaluation testbed that executes LLM-backed AgentCards through HTTP protocol endpoints and evaluates trust, authorization, protocol interoperability, shared knowledge, audit provenance, interconnection leakage, ecosystem power imbalance, and human agency risks.

避免表述为：

> We fully reproduce a real-world Internet of Agents ecosystem.
