# 方案与代码实现对照

本表是设计文档与实际代码之间的边界。状态只使用“已实现、部分实现、未验证”，不把测试通过写成科研有效。

|---|---|---|---|
| 公共 System Prompt 与角色输入隔离 | `context_builder.py`、`prompt_policy.py` | 已实现 | 初始提示已移除 IoA、风险类别和标准答案字段 |
| 六字段自由业务决策 | `models.py`、`behavior_parser.py` | 已实现 | 最终输出为 status、decision、answer、evidence_refs、next_action、handoff_message |
| 原生工具请求与多轮返回 | `llm_runtime.py`、`gateway.py` | 已实现 | 工具轮和最终六字段仍通过兼容层衔接 |
| 后台隐藏行为派生 | `hidden_behavior.py` | 部分实现 | 已覆盖主要类别，但否定语义和 Artifact 交接仍有待修反例 |
| 八类流程 | `categories/` | 已实现 | 八类均可运行，但场景真实性与最终方案不完全一致 |
| 真实业务角色和角色专属工具 | `categories/`、`tools/runtime_registry.py` | 部分实现 | 现有工具仍偏通用，CAS 未完整实现最终方案中的行程工具链 |

| 八项正式实验 | `scripts/run_agent_model_suite.py` | 未验证 | 尚无满足全部正式门槛的完整运行 |

## 当前执行主链

```text
run_agent_model_suite.py
  -> suite_runner.py
  -> categories/<category>.py
  -> step_executor.py
  -> IoAEnvironment / Gateway / Runtime / ToolGateway
  -> evidence_builder.py / judge.py / trace_export.py
```

任何方案调整都应先更新当前方案，再更新本表，最后修改代码和测试。
