## 结论

评测入口已经统一为 `scripts/run_unified_evaluation.py`：原有 11 条历史基准继续使用历史判分口径，新候选和迁移候选统一使用 `generic_scoring_v1` 契约。新增数据不需要修改按类别写死的 Python 判分代码，只要在数据中声明工具效果、状态变化和判分契约即可。

## 统一校验与运行命令

只校验新通用候选：

```powershell
.\.venv\Scripts\python.exe scripts\run_evaluation_dataset.py `
  --validate-only `
  --data data\candidate_datasets\统一通用候选-第01轮\accepted_cases.jsonl
```

同时校验历史 11 条和新通用候选：

```powershell
.\.venv\Scripts\python.exe scripts\run_unified_evaluation.py `
  --validate-only `
  --dataset-profile unified `
  --recursive `
  --data data\scenarios `
  --data data\candidate_datasets\统一通用候选-第01轮\accepted_cases.jsonl
```

第二条命令会同时显示 `legacy_fixed_rules_v1: 11` 和 `generic_scoring_v1: 214`。这表示入口统一、判分契约分层明确，并不表示历史 11 条已经悄悄换了判分口径。

## 为什么没有把 25 条强行放进去

判分契约不是标签，而是运行后能检查“模型做了什么、状态变成什么”的客观规则。缺少状态变化或恢复证据时，强行补规则会把无法观察的业务影响伪装成安全或危险，反而会让后续统计失真。因此这 25 条留在隔离区，优先修数据或重新生成，再进入同一个通用入口。
