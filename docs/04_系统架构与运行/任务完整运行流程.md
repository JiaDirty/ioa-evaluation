# 任务完整运行流程

Agent 式任务和后台任务共用同一组任务 API。默认只提交自然语言目标和约束：

```json
{"prompt": "自然语言任务", "constraints": {}, "execution_mode": "agentic"}
```

## 内部执行状态

`AgenticOrchestrator` 使用以下详细状态：

```text
RECEIVED（已接收）
  -> SPECIFYING（整理任务）
  -> PLANNING（制定计划）
  -> EXECUTING（执行）
  -> WAITING_HUMAN_INPUT（等待人工输入）
  -> REPLANNING（重新规划）
  -> SYNTHESIZING（汇总）
  -> SECURITY_REVIEW（安全检查）
  -> COMPLETED / FAILED / CANCELLED
```

当 Agent 动作或高影响操作需要用户明确确认时，任务进入 `WAITING_HUMAN_INPUT`。提交人工决定的接口为：

```text
POST /api/tasks/{task_id}/human-input
```

请求需要包含 `checkpoint_id`、`approved`，还可以包含结构化 `input` 和用户 `comment`。

## 对外任务状态

- `QUEUED`：任务已经保存，但后台执行程序尚未开始；
- `RUNNING`：后台程序已经开始通过 Gateway 执行；
- `WAITING_HUMAN_APPROVAL`：等待高风险操作或人工参与环节确认；
- `COMPLETED`：任务完成，可以读取结果、事件、产物和工具历史；
- `FAILED`：执行报错或返回失败结果；
- `CANCEL_REQUESTED`：已经请求取消，等待执行程序处理；
- `CANCELLED`：任务已在执行前或执行中取消；
- `RETRYING`：为更完整的重试策略保留。当前重试会根据原请求新建一个排队任务。

## 任务 API

- `POST /api/tasks`：新建任务；
- `GET /api/tasks`：查看任务列表；
- `GET /api/tasks/{task_id}`：查看任务基础信息；
- `GET /api/tasks/{task_id}/detail`：查看完整详情；
- `GET /api/tasks/{task_id}/events`：查看事件；
- `GET /api/tasks/{task_id}/tool-calls`：查看工具调用；
- `GET /api/tasks/{task_id}/artifacts`：查看产物；
- `GET /api/tasks/{task_id}/execution-graph`：查看执行图；
- `POST /api/tasks/{task_id}/cancel`：取消任务；
- `POST /api/tasks/{task_id}/retry`：重新运行。
