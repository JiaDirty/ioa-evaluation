# IoA 测评数据与架构深度评估

## 结论

完整运行数据需要比普通问答数据复杂，但生成模型和人工作者没有必要直接手写全部复杂字段。这个项目测的不是“模型会不会回答一道题”，而是智能体在多角色业务链中看到什么、调用什么工具、实际改变什么状态、错误是否传播、最后能否恢复。要让结论可复现，运行层必须保存这些信息。

正确做法不是把完整数据粗暴删短，而是分成两层：作者层只描述业务差异和安全判据；本地编译器生成完整运行结构。当前代码已经实现这条路线，但作者层仍有继续精简的空间。

框架目前是一个较完整、可扩充的受控智能体安全评测基线，但不能称为“已经完美”。新数据可以使用任意新工具名、状态字段和步骤编号，不需要增加 Python 判分类别分支；原 11 条历史场景为了保持已有实验可复现，仍通过兼容适配器走旧专用逻辑。因此对外入口已经统一，内部迁移尚未彻底完成。

## 为什么普通问答格式不够

如果一条数据只有“Prompt + 标准答案”，最多能判断最终文字回答。它无法可靠回答：

- 模型是否已经产生危险工具调用意图；
- 工具是否成功执行，还是调用被参数或前置条件阻断；
- 危险信息是否从一个角色传播到下一个角色；
- 最终业务状态是否真的受到影响；
- 正常证据与风险证据之间是否只有一个目标变量；
- 错误发生后，恢复步骤是否处理了同一笔真实业务事件。

因此完整运行层需要场景输入、角色步骤、工具定义、状态效果、执行计划、判分契约和来源信息。它更像一个“可执行实验说明书”，不是传统的一问一答样本。

## 哪些复杂度必须保留

必须保留的内容包括：每个角色真实可见的记录与上游产物、步骤依赖、工具参数 Schema、确定性工具返回、参数如何写入业务状态、正常与风险条件的单一差异、恢复所针对的风险来源，以及安全意图、危险意图、实际动作和最终影响的客观判据。

这些内容直接影响模型看到什么、工具做了什么和最后怎样判分。删掉后仍然可以产生一个结果文件，但结果可能无法解释、无法复现或无法证明是目标机制导致。

## 哪些复杂度不应让模型手写

以下内容属于机械展开：全局唯一编号、类别代码、批次和模型来源、同一工具在多个条件中的重复定义、状态绑定的运行对象、同一行为的意图规则和动作规则、规则编号、请求参数回显和布尔自审表。

当前简洁作者格式已把这些内容移到本地编译器。模型只写四件事：业务流程、正常/风险输入、工具及其真实效果、各条件下的安全/危险行为与最终状态。编译器随后生成完整 `BusinessCaseSpec` 和 `generic_scoring_v1` 判分契约。

不过，当前作者格式还不能称为真正轻量。第三轮覆盖试跑中，27 条通过确定性校验的候选平均作者层大小约 37 KB，完整运行层平均约 42 KB，平均只减少约 11%。88 次模型调用中，初次直接展开成功 25 次，最新版编译器重编译后共接纳 27 次。失败原因既包括模型写错字段，也包括因果对照、工具状态和安全/危险判据不自洽。这说明“两层架构”方向正确，但下一版作者层还应继续把可推导的工具状态绑定和规则展开交给本地编译器。

## 当前架构做得比较好的部分

1. 数据、运行和判分已分层。模型可见业务内容与评审侧规则分开，判分答案不会直接进入模型 Prompt。
2. 工具执行有真实轨迹。系统分别保存工具意图、成功或失败结果、动作前状态和动作后状态，不把“模型想调用”误当成“业务已经发生”。
3. 判分分为意图、动作和最终影响。模型可以有危险意图但工具失败，也可以动作安全但未完成恢复，结果不会被压成一个含糊标签。
4. 新数据采用声明式判分。新增工具名、状态字段和行业场景无需修改 Python 判分代码。
5. 正常、风险和恢复形成因果配对。通用执行计划支持独立运行或共享前缀分叉，恢复从真实风险状态继续。
6. 数据准入较严格。字段、时间、依赖、工具引用、状态绑定、判分覆盖、条件泄漏和典型路径都在调用真实被测模型前校验。
7. 历史结果可复现。原 11 条由清单和哈希锁定，架构升级不会悄悄改变已经完成的八项实验口径。
8. 统一入口可同时加载历史基准和通用数据，并明确拒绝未知的无契约数据，避免新候选误落入旧硬编码判分。

## 仍然存在的边界

1. 原 11 条内部仍有类别专用运行和判分代码。兼容适配器是有意保留的迁移边界，不是真正的单轨实现。
2. 本地校验只能证明结构和声明逻辑一致，不能独立证明业务场景现实、语言自然或论文结论有代表性。
3. 六条典型路径演算不能穷举模型在同一步骤连续调用多个工具、伪造参数或走非常规组合的所有情况，仍需模型互审和人工审核。
4. 当前工具环境是受控模拟，不是直接连接真实医院、金融或生产系统；它适合可复现实验，不等同于真实系统集成测试。
5. 多角色流程按声明顺序执行并传递产物，适合当前测评，但不是支持任意并发、循环协商和动态拓扑的通用多智能体平台。
6. 生成模型能力差异明显。作者格式降低了格式失败，但不能替代模型对因果对照、恢复绑定和严谨判分的理解。
7. 当前作者层仍然偏重。它已避免生成完整运行结构，但仍要求模型同时设计工具效果、状态变化和多层判据，首轮跨模型覆盖试跑只有 27/88 通过确定性准入。

## 推荐的最终形态

短期保留原 11 条不变，把所有扩充数据建立在作者格式和通用运行路径上。候选经过编译、确定性审计、非生成模型互审和人工/外包审核后，每个可运行测评项保留 5 条正式数据。

中期为原 11 条另建通用等价副本，不覆盖原文件。用相同被测模型、相同输入快照分别跑旧路径和通用路径，逐层比较工具意图、动作、最终状态和判分。只有等价性证据稳定后，才把通用副本设为默认，并把旧专用代码降为历史回归适配器。

长期如果需要评价模型输出中的复杂语义真实性，可以增加独立语义裁判作为辅助证据，但核心安全判分仍应优先依赖工具调用和业务状态等可审计事实，不能让一个裁判模型替代全部客观规则。
