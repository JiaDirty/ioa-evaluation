# Agent 模型安全测评记录说明

每次测评在 `results/agent_model/<运行编号>/` 下生成以下文件：

| 文件 | 用途 |
|---|---|
| `context.db` | 权威事件与状态数据库，供复核和重新计算指标使用 |
| `execution_trace.jsonl` | 逐步骤原始记录，每行一个完整 JSON 对象，适合程序处理 |
| `execution_trace.md` | 中文逐步报告，适合直接阅读或放入文档系统 |
| `execution_trace.html` | 可折叠、可搜索的时间线页面，双击即可在浏览器打开 |
| `trace_summary.json` | 模型调用、工具调用、耗时、重试和用量汇总 |
| `run_results.json` | 八项测评的指标、判定和成对结果 |
| `run_manifest.json` | 数据、代码、模型配置、顺序和文件校验值 |

## 每个 Agent 步骤记录的内容

- 案例、基准/风险/恢复过程、轮次、角色和实际选中的 Agent。
- 最终发送给模型的 system/user messages 与请求参数。
- 模型服务返回的原始内容、解析后内容和解析错误。
- 输入输出用量、调用耗时和重试次数。
- 完整模型可见状态、历史、上游产物和工具描述。
- 工具调用参数、返回结果、状态和调用编号。
- 新产物、父产物、转发关系和状态变化事件。
- 事件顺序、时间、因果关系、幂等键和内容校验值。

如果模型调用失败，失败请求、错误、已发生的重试和已选择的 Agent 仍会写入记录。

## 阅读建议

日常人工检查优先打开 `execution_trace.html`，使用页面顶部搜索框筛选案例、角色或 Agent。论文复核时同时保留 `context.db`、`execution_trace.jsonl` 和 `run_manifest.json`；Markdown/HTML 是便于阅读的导出视图，不取代数据库中的原始事件。

## 脱敏边界

导出时会移除 API 密钥、认证头、密码、访问令牌和 Cookie。测评本身需要的确认凭证、受控工具参数和合成夹具标识不会被误删。原始模型输入与输出可能包含受控实验内容，因此正式结果目录仍应按研究数据管理要求保存。
