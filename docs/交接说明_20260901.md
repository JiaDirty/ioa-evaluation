# IOA 测评项目交接说明（2026-09-01）

## 当前目标

本阶段已经完成统一数据架构：11 条历史数据、440 条候选和未来数据都先进入 `ScenarioTask`，再按
`ScenarioKernel`、`EffectSpec`、`CompiledCase` 顺序处理。生产状态、文件和依赖由单一
`PipelineOrchestrator` 与 `registry.json` 管理。

本阶段明确不调用 AI Hub Mix，不运行真实模型，也不把离线结构通过当成业务质量结论。

## 已实现

- `src/evaluation/scenario_generation/pipeline_models.py`：版本化的 ScenarioKernel、EffectSpec、manifest 模型、哈希绑定。
- `src/evaluation/scenario_generation/pipeline.py`：旧候选提取、作者稿物化、严格条件映射和本地编译。
- `src/evaluation/scenario_generation/path_validation.py`：正常安全、正常危险、风险安全、风险危险、恢复成功、恢复失败六路径离线演算，并输出工具调用、状态变化和终态证据。
- `src/evaluation/scenario_generation/pipeline_runner.py`：旧版离线证据兼容适配器，不作为新生产入口。
- `src/evaluation/scenario_generation/unified_pipeline.py`：旧版 registry 构建兼容适配器，不作为新生产入口。
- `src/evaluation/scenario_generation/unified_architecture.py`：四层数据模型、单一 Registry、严格状态机和 PipelineOrchestrator。
- `scripts/migrate_to_unified_tasks.py`：将历史数据和候选一次性迁移为 ScenarioTask。
- `scripts/run_canonical_pipeline.py`：统一提交、处理和续跑入口。
- `scripts/run_scenario_pipeline.py`：旧版离线证据命令，仅用于历史复现。
- `scripts/build_unified_registry.py`：旧版 manifest registry 构建命令，仅用于历史复现。
